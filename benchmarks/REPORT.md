# Jev 两阶段策略真实 API 对照报告

> 2026-09-22 后续：`behavior-v3` 根据玩家导出的 40 局真实记录继续优化。V3 没有在这份数据上重新调 API 参数，而是用逐局只看过去信息的离线重放比较动作策略。实际记录中 Jev 为 11 胜、6 平、23 负（27.5%）；人类换拳率 59.0%，针对 Jev 上一拳的反制率为 43.6%，且人类刚获胜后的反制率为 54.5%。旧版组合预测命中 33.3%，V3 的生产动作策略重放为 21 胜、7 平、12 负，胜率 52.5%。这份重放使用同一批真实数据和逐局只看过去信息的证据，不是独立验证，也不证明对任意玩家都能达到该胜率。

2026-09-22（新加坡时间）。最终版本：`behavior-v2`。

最终保留验证中，原版与新版各打 100 局，Jev 胜率从 **42% 提升到 70%**，增加 28 个百分点。胜率分母包含平局。每种模拟对手只有 25 局，这不是对真实玩家总体胜率的估计，也不能证明局数越多胜率必然越高。

## 实际调用与公平约束

- 共 7 组，每组恰好 100 次真实 TypeSafe 请求：700 次调用、450 局、0 次请求失败、0 次重试。实际返回模型均为 `jev-1.13.0`，请求模型为 `jev-latest`。
- 原版每局 1 次请求；新版每局 2 次，因此新版每个 100 请求组只有 50 局。每轮对照用一个原版组和两个新版组，保证双方各 100 局。
- 程序在请求前私下确定模拟人类的当前出拳。当前拳、未来拳、模拟规则、种子和对手名称都不进入 Jev 请求。Jev 仅收到已完成历史及其统计。
- 两个版本使用相同对手规则与种子。会针对 Jev 作出反应的对手依赖各自对局的实际历史，因此不能宣称两版面对完全相同的出拳序列。
- 最终出拳直接使用第二次 Jev 返回的 `choice`，程序没有替换它，也没有用随机结果代替 API 错误。
- 两次调用均在玩家按钮启用前完成。先封存出拳，再允许选择；揭盖和结算只解封同一选择，不再调用模型。
- 本报告和原始记录不包含 API Key。

## 调整过程与调参数据

第一轮 300 次请求，在循环、输赢后换拳、途中换套路、随机四类对手上，原版总胜率 36%，V1 为 69%。V1 对途中换套路者的后 10 局胜率只有 50%，暴露了旧规律权重下降过慢的问题。

V2 增加快速遗忘的预测权重与最近 6 次预测命中记录，让第一次 Jev 返回的策略变化分数实际控制近期预测的混合比例。随后用 100 次请求复测两个调参对手：

| 调参对手 | 原版 | V1 | V2 |
| --- | --- | --- | --- |
| 输赢后换拳（种子 228） | 24% | 84% | 84% |
| 途中换套路（种子 337） | 56% | 72% | 88% |

每格 25 局。换套路者 V2 的后 10 局胜率为 90%。这些结果用于调整方案，不作为独立验证结果。

调参记录：[train-behavior-v1.json](train-behavior-v1.json)、[refine-behavior-v2.json](refine-behavior-v2.json)。

耗时是请求计时之和除以完成局数；新版已合计两次串行调用，不是单次调用时长，也不含本地并发队列等待或页面交互时间。各组分时执行，不能把 refine 组的短延迟归因于策略优化。

最终对照中，原版平均每局约 1.90 秒、1,091 输入 tokens；新版约 3.65 秒、5,775 输入 tokens。新版每局输入量约为原版 5.3 倍，输出平均从 40 增至 140 tokens。完整历史继续增长时，输入量还会增加；本报告没有推算货币费用。

## 行为值的用途与证据边界

规律、狡猾、失稳、策略变化四个数值由第一次 Jev 请求结合可观察统计打分，第二次请求接收实际结果。策略变化还会直接改变短期预测权重。29 种预测方法的表现通过逐局先预测、后更新评估，避免把目标答案提前交给预测器。完整提示词、指标与三张图见 [STRATEGY.md](../STRATEGY.md)。

“失稳”只表示输棋后的出拳变化，不代表真实崩溃或心理诊断。少于 8 局未揭盖样本不展示行为数值；失稳还要求至少 4 次输棋后转移。模型的 confidence 是分布集中程度，不是实际准确率。

本实验比较的是“统计预测 + 行为评分 + 两阶段提示词”的组合效果，没有做去除情绪分数的消融实验，不能把提升单独归因于情绪计算。也没有证明模型参数在训练或对任何人类都能获胜。
